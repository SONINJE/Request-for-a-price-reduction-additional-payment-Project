# 판매가 인하 / 추가금 요청 관리 프로그램

기존 엑셀( `판매가_인하_추가금_요청_리스트.xlsx` )의 업무를 대체하기 위한
**WPF(C#) + C++ 네이티브 엔진** 데스크톱 프로그램입니다.

> **실행 시 비밀번호(`1234`)를 한 번 확인합니다.** 강력한 보안이 아니라, 사내 전용 도구를
> 아무나 실수로 건드리지 못하게 막는 용도입니다. 비밀번호는 `WpfPriceApp/AppConfig.cs` 에서
> 바꿀 수 있습니다.

## 설치해서 바로 쓰기

개발 환경 없이 바로 설치해서 쓰려면 `installer\out\PriceCalcAppSetup.msi` 를 실행하세요.
.NET 런타임을 따로 설치할 필요 없이(자체 포함 배포) 설치 후 시작 메뉴/바탕화면 바로가기로
바로 실행할 수 있습니다. 자세한 사용법은 [`docs/사용자매뉴얼.docx`](docs/사용자매뉴얼.docx) 를 참고하세요.

설치 파일이 없거나 소스를 수정한 뒤 새로 만들어야 한다면:

```powershell
installer\build_installer.ps1
```

위 스크립트가 솔루션 빌드 → self-contained 게시 → `installer\out\PriceCalcAppSetup.msi` 생성까지
한 번에 처리합니다 (Visual Studio 2022, .NET 8 SDK 필요).

## 구성

```
PriceCalcApp.sln
├─ PriceCalcEngine/     C++ 계산 엔진 (DLL) — Visual Studio 2022, x64
│   ├─ include/RowEngine.h      정방향/역산 계산 로직 (제약 전파 방식)
│   ├─ include/EventModel.h     행사(이벤트) JSON 모델
│   ├─ include/DllApi.h         WPF 에서 P/Invoke 로 부르는 C API
│   ├─ src/*.cpp
│   ├─ third_party/json.hpp     nlohmann/json (헤더 1개, 이미 포함됨)
│   └─ tests/test_main.cpp      Windows 없이도 로직만 확인하는 콘솔 테스트
└─ WpfPriceApp/         WPF(C#) UI — .NET 8, net8.0-windows
    ├─ Models/          ProductRow / EventFile (JSON 스키마)
    ├─ ViewModel/        MainViewModel, 필드 정의, 계산 요청/응답
    ├─ Interop/          NativeEngine (P/Invoke 래퍼)
    ├─ Views/            간단한 입력 다이얼로그
    ├─ Themes/Colors.xaml 화이트 톤 UI 테마
    └─ Events/           원본 엑셀에서 추출한 실제 행사 데이터 (JSON, 24개)
```

## 빌드 방법 (Visual Studio 2022)

1. `PriceCalcApp.sln` 을 Visual Studio 2022 로 엽니다. (Desktop C++ 워크로드,
   .NET 데스크톱 개발 워크로드가 설치되어 있어야 합니다.)
2. 플랫폼을 **x64** 로 맞춥니다 (두 프로젝트 모두 x64 로 설정되어 있습니다).
3. `PriceCalcEngine` 프로젝트를 먼저 빌드합니다 → `PriceCalcEngine.dll` 생성.
4. `WpfPriceApp` 프로젝트를 빌드/실행합니다.
   - `WpfPriceApp.csproj` 에 `PriceCalcEngine.dll` 을 빌드 출력 폴더로 자동 복사하는
     설정이 들어있습니다 (두 프로젝트가 같은 솔루션 폴더 아래 있어야 함).
   - 만약 DLL 을 찾지 못한다는 오류가 나면, `PriceCalcEngine\x64\Debug\PriceCalcEngine.dll`
     파일을 `WpfPriceApp` 실행 폴더( `bin\x64\Debug\net8.0-windows\` )에 직접 복사하세요.
5. 처음 실행하면 `Events/` 폴더의 샘플 행사(원본 엑셀에서 추출한 실제 데이터)가
   왼쪽 목록에 나타납니다.

## 사용 방법

- **로그인**: 프로그램을 실행하면 비밀번호(`1234`) 확인 창이 먼저 뜹니다. 맞게 입력해야
  프로그램이 열립니다.
- **행사 목록 & 조회 날짜(범위)**: 왼쪽 목록 위의 "조회 날짜"는 **시작~종료 범위**로 지정합니다.
  기본값은 오늘 하루이며, 이 범위와 행사 기간이 겹치는 행사만 목록에 보여줍니다. 기간이
  지정되지 않은 행사는 항상 보입니다. 모든 행사를 다시 보려면 "전체보기" 버튼을 누르세요.
- **행사 삭제**: 왼쪽 목록에서 행사를 선택하고 "선택 행사 삭제" 버튼을 누르면, 삭제 확인
  후 **비밀번호를 다시 한 번 입력**해야 실제로 삭제됩니다 (되돌릴 수 없는 작업이라 매번 확인).
- **행사 만들기/불러오기**: 왼쪽에서 새 행사를 만들거나 목록에서 더블클릭해 불러옵니다.
  행사 하나 = JSON 파일 하나로 저장됩니다.
- **행사명 / 기간 / 메모 / 저장**: 오른쪽 위 "행사 정보" 카드 하나에 모여 있습니다.
  행사명 → 행사 기간(시작일~종료일 달력 선택, 테두리로 한 묶음처럼 보이게 배치) → 메모를
  입력한 뒤, **같은 카드 안의 "저장" / "다른 이름으로 저장" / "JSON 다운로드(공유용)"
  버튼**으로 바로 이어서 저장합니다.
- **JSON 다운로드(공유용)**: 현재 행사를 먼저 저장한 뒤, 원하는 위치(기본값: 바탕화면)로
  JSON 파일을 복사합니다. 팀원에게 메신저/메일로 보내기 위한 용도입니다.
- **저장 폴더 열기**: 왼쪽 목록 아래 버튼 — 행사 JSON이 실제로 저장되는
  `%LOCALAPPDATA%\PriceCalcApp\Events` 폴더를 탐색기로 바로 엽니다.
- **상품 추가**: "상품 추가" 버튼 → 품목(상품명)을 목록에서 고르거나 새로 입력합니다.
  **품목 마스터에 등록된 상품이면 SKU·채널·매입가(+)·기존정산액(+)이 자동으로 채워집니다**
  (실제 엑셀의 VLOOKUP과 같은 역할). 등록되지 않은 새 상품이면 빈 값으로 추가되니
  나중에 "품목 마스터 관리"에서 등록해두면 다음부터 자동으로 채워집니다.
- **품목 마스터 관리**: 툴바의 "품목 마스터 관리" 버튼 → 상품명/SKU/매입가(VAT+)/행사가/
  스팟가/지원금(vat+)\_S·E·R/채널/비고를 표에서 직접 추가·수정·삭제할 수 있습니다
  (`MasterData.json`, 실제 엑셀의 "Master" 시트에 대응).
- **값 편집 & 역산**: 표에서 상품을 선택하면 아래쪽에 값 카드가 나타납니다.
  각 카드의 체크박스(🔒)를 켜면 그 값을 직접 입력하는 값(고정값)으로,
  끄면 자동으로 계산되는 값(역산 대상)으로 취급됩니다.
  - **반드시 정확히 8개**를 고정해야 나머지가 유일하게 계산됩니다.
  - 예: 판매가/배송비/수수료/매입가(+)/기존정산액(+)/캡슐금액/쿠폰액 분담 쿠폰을 고정하고,
    "추가요청금액(+)" 대신 "최종마진율"을 고정해서 5%를 입력하면 → 그 마진율을 맞추기 위해
    필요한 추가요청금액이 역산됩니다.
  - 값을 다 입력했으면 "역산/계산 실행" 버튼을 누릅니다.
  - **기지원금**은 ROUNDUP이 들어간 단방향 계산값이라 잠글 수 없습니다 — 마진액과
    정산액포함매입가(+)가 둘 다 정해지면 자동으로 표에 채워집니다.
- **엑셀처럼 복사/붙여넣기**: 상품 표의 셀을 클릭·드래그로 범위 선택한 뒤 `Ctrl+C`로 복사,
  `Ctrl+V`로 붙여넣기가 됩니다. 행 단위, 열 단위, 셀 범위 단위 모두 가능하고 엑셀에서 표를
  복사해와 그대로 붙여넣을 수도 있습니다. 셀을 더블클릭하거나 바로 타이핑해서 직접 값을
  고쳐도 됩니다. 붙여넣기는 이미 있는 상품 행 범위 안에서만 채워지며(행이 모자라면 상품을
  먼저 추가), 값을 붙여넣어도 잠금(🔒) 상태는 바뀌지 않습니다.
- **CSV 내보내기**: 현재 행사의 상품 표를 CSV 로 저장 (엑셀에서 바로 열림, 한글 깨짐 방지용 BOM 포함).
  컬럼 순서는 그리드와 동일하게 **원본 엑셀 컬럼 순서**(비고가 최종마진율 다음, 예상수량 앞)를
  따릅니다.

## 계산 로직 (역산이 항상 되는 이유)

실제로 쓰고 있는 최신 엑셀(2026-09 기준)의 각 컬럼은 아래 8개의 수식으로 서로 묶여 있습니다.

| 수식 | 관련 값 |
|---|---|
| 채널>공급가 = 판매가 × (1-수수료) | 판매가, 수수료, 채널>공급가 |
| 정산액포함매입가(+) = 매입가(+) - 기존정산액(+) | 매입가(+), 기존정산액(+), 정산액포함매입가(+) |
| 마진액 = 채널>공급가 - 정산액포함매입가(+) - 배송비 - 캡슐금액 - 쿠폰액 분담 쿠폰 | 위 5개, 마진액 |
| 추가요청금액(-) = 추가요청금액(+) / 1.1 | 추가요청금액(+), 추가요청금액(-) |
| 최종마진액 = 추가요청금액(+) + 마진액 | 추가요청금액(+), 마진액, 최종마진액 |
| 최종마진율 = 최종마진액 / 채널>공급가 | 최종마진액, 채널>공급가, 최종마진율 |
| 본사(확인용)vat+ = 추가요청금액(+) + 기존정산액(+) | 추가요청금액(+), 기존정산액(+), 본사(확인용)vat+ |
| 본사(확인용)vat- = 본사(확인용)vat+ / 1.1 | 본사(확인용)vat+, 본사(확인용)vat- |

역산 가능한 변수는 총 16개, 수식은 8개이므로 **8개 값을 입력하면 나머지 8개가 정해집니다.**
`RowEngine.cpp` 는 특정 조합을 하드코딩하지 않고, "값이 이미 정해진 변수들로부터
아직 모르는 변수를 하나씩 풀어나가는" 방식(제약 전파)을 쓰기 때문에,
사용자가 **어떤 8개를 고정하든** 풀 수 있는 조합이면 자동으로 역산됩니다.
(풀 수 없는 조합이거나 값끼리 모순이면 화면에 안내 메시지가 표시됩니다.)

**기지원금**은 `ROUNDUP(ABS(마진액) + 정산액포함매입가(+)×5%, -3)` 으로 계산되는데,
ROUNDUP은 정보가 손실되는 연산이라 역으로 풀 수 없습니다. 그래서 이 값은 위 8개 수식
그래프에 넣지 않고, 마진액과 정산액포함매입가(+)가 둘 다 정해졌을 때 한 번 순방향으로만
계산해서 채웁니다 — 잠글 수 없는 "표시 전용" 값입니다.

**SKU / 채널 / 매입가(+) / 기존정산액(+)** 은 상품 추가 시 상품명으로 품목 마스터를 찾아
자동으로 채워지지만(실제 엑셀의 VLOOKUP과 동일), 채워진 뒤에는 다른 값과 똑같이 취급되어
잠그거나 풀어서 역산 대상으로 삼을 수 있습니다.

## 알려진 이슈 수정 이력

- **빌드 실패(코드페이지 오류)**: C++ 엔진 소스가 BOM 없는 UTF-8이라 MSVC가 시스템 코드페이지(949)로
  잘못 해석해 컴파일이 깨지던 문제 → `PriceCalcEngine.vcxproj` 에 `/utf-8` 옵션 추가로 해결.
- **DLL 배포 경로 불일치**: `.sln` 으로 빌드하면 `PriceCalcEngine.dll` 이 `WpfPriceApp.csproj` 가
  기대하는 `PriceCalcEngine\x64\<Config>\` 가 아니라 솔루션 최상위 `x64\<Config>\` 에 생성되어,
  Debug 빌드는 DLL이 아예 복사되지 않고 Release 빌드는 옛 DLL이 그대로 남는 문제가 있었음 →
  `PriceCalcEngine.vcxproj` 에 `OutDir`/`IntDir` 을 프로젝트 폴더 기준으로 고정해 해결.
- **한글 파일명 로드/저장 실패**: `EventModel.cpp` 가 UTF-8 파일 경로를 narrow-char
  `std::ifstream`/`std::ofstream` 으로 그대로 열어, Windows가 이를 시스템 코드페이지로 해석하면서
  한글이 포함된 모든 행사 파일에서 "파일을 찾을 수 없습니다" 오류가 발생하던 심각한 버그 →
  UTF-8 경로를 UTF-16으로 변환해 여는 방식으로 수정.
- **저장 데이터 위치**: 행사 JSON과 채널/품목 목록을 설치 폴더(Program Files) 밑에 두면 관리자
  권한이 없는 일반 사용자는 쓰기가 막힐 수 있음 → `%LOCALAPPDATA%\PriceCalcApp\` 으로 이전.
  최초 실행 시 설치 폴더에 내장된 샘플 행사 24개를 이 폴더로 자동 복사.

## 신규 기능

- **행사 기간 날짜 선택**: `MainWindow.xaml` 의 기간 입력이 자유 텍스트 `TextBox` 에서
  `DatePicker` 2개(시작일/종료일)로 바뀌었습니다. `EventFile` 의 `period` 필드는
  `startDate`/`endDate` 로 대체되었습니다 (C++/C# 양쪽 모델 동일하게 수정).
- **채널 & 품목 마스터 목록**: `ProductRow` 에 `channel` 필드가 추가되었고, 상품 추가 시
  뜨는 창(`AddProductDialog`)에서 품목/채널을 드롭다운으로 고르거나 새로 입력할 수 있습니다.
  목록은 "채널/품목 관리" 버튼(`MasterDataWindow`)에서 직접 추가/삭제할 수 있고,
  `%LOCALAPPDATA%\PriceCalcApp\MasterData.json` 에 저장됩니다.
- **조회 날짜 필터 / JSON 다운로드 / 저장 폴더 열기**: 왼쪽 목록에 오늘 날짜 기본 필터,
  "행사 정보" 카드에 팀 공유용 JSON 다운로드 버튼, 저장 폴더를 탐색기로 여는 버튼을 추가했습니다.
- **로그인 + 행사 삭제**: `App.xaml.cs` 의 `OnStartup` 에서 비밀번호(`1234`) 확인 창
  (`PasswordDialog`)을 먼저 띄우고, 통과해야 `MainWindow` 를 생성합니다. 왼쪽 목록에 "선택
  행사 삭제" 버튼을 추가했고, 삭제는 되돌릴 수 없으므로 **매번** 비밀번호 확인을 거칩니다.
- **그리드 엑셀식 범위 선택/복사·붙여넣기**: `MainWindow.xaml.cs` 에서 `Ctrl+V` 를 직접
  처리해 엑셀에서 복사한 표를 그대로 붙여넣을 수 있습니다. `ProductRowViewModel` 의 숫자
  속성에 setter를 추가했고, 컬럼 순서/CSV 순서/붙여넣기 열 매핑은 `ViewModel/GridColumns.cs`
  하나로 통일했습니다 — 이 파일 하나만 고치면 세 곳이 동시에 맞습니다. (그리드 자체는
  `IsReadOnly=True` 로 직접 타이핑은 막고, 값 변경은 아래 값 편집 패널에서 하도록 함 — 셀
  선택 모드를 `Cell` 로 하면 행 클릭으로 값 편집 패널이 안 열리는 문제가 있어 기본값을 씀.)
- **조회 날짜 범위 지정**: `FilterDate` 단일 값을 `FilterStartDate`/`FilterEndDate` 범위로
  바꾸고, 구간 겹침(interval overlap) 방식으로 필터링합니다.

## 2.0.0 — 실제로 쓰는 최신 엑셀 구조로 전면 개편

사용자가 실제로 쓰고 있는 최신 엑셀 파일을 직접 열어 수식까지 확인한 뒤, 계산 엔진을
그 구조에 맞게 다시 설계했습니다 (이전 버전은 훨씬 단순화된 옛 구조를 따르고 있었음).

- **필드 구성 변경**: 원가/실원가/기존지원금 → 매입가(+)/정산액포함매입가(+)/기존정산액(+)
  으로 이름과 구조를 맞추고, `SKU`/`행사유형` 컬럼과 `캡슐금액`/`쿠폰액 분담 쿠폰`/
  `본사(확인용)vat+`/`본사(확인용)vat-`/`기지원금` 5개 필드를 새로 추가했습니다.
  `예상수량`/`예상추가비용`은 최신 엑셀에 더 이상 없어 제거했습니다 (관련 `ComputeTotals`
  API도 같이 정리).
- **품목(SKU) 마스터 도입**: 기존의 단순 "채널/품목 이름 목록"을 실제 엑셀의 "Master" 시트에
  대응하는 `MasterProduct` 카탈로그(SKU/매입가/행사가/스팟가/지원금\_S·E·R/채널/비고)로
  바꿨습니다. 상품 추가 시 상품명으로 이 카탈로그를 찾아 SKU/채널/매입가(+)/기존정산액(+)을
  자동으로 채웁니다(VLOOKUP과 동일한 역할). 관리 화면(`MasterDataWindow`)도 표 형태로
  다시 만들었습니다.
- **역산 자유도 7 → 8**: 새 필드 그래프는 변수 16개·수식 8개라 정확히 8개를 고정해야
  나머지가 결정됩니다. `기지원금`은 `ROUNDUP` 때문에 역으로 풀 수 없어 이 그래프에서 빼고
  마진액·정산액포함매입가(+)가 둘 다 정해지면 순방향으로만 계산합니다.
- **구버전 파일 자동 마이그레이션**: `EventModel.cpp` 에서 옛 필드 이름(`existingSubsidy`,
  `cost`, `realCost`)을 새 이름으로 값과 잠금 상태 모두 옮겨줍니다 — 구버전으로 저장된
  행사 파일을 열어도 값이 사라지지 않습니다 (`예상수량`/`예상추가비용`만 새 구조에 없어
  버려집니다).

## 2.1.0 — 상품 추가 창 개편 / 그리드 가로 스크롤 제거 / 열 선택 복구 / 입력창 디자인 개선

- **상품 추가 창에서 품목 마스터 직접 관리**: `AddProductDialog` 를 다시 만들어, 상품을
  추가할 때 품목 마스터 전체 목록이 검색 가능한 리스트로 함께 뜹니다. 이름을 검색해서
  기존 품목을 고르거나, 그 자리에서 "새 품목 등록"으로 마스터에 새 항목을 추가하고
  "선택 삭제"로 지울 수 있습니다 — 이전처럼 별도로 "품목 마스터 관리" 창을 열 필요가
  없습니다(그 창은 그대로 남아있고, 여기서 바꾼 내용과 같은 목록을 공유합니다).
- **그리드 가로 스크롤 제거**: 22개 상품 컬럼이 `Width="Auto"` 로 내용(특히 긴 상품명)에
  맞춰 늘어나면서 창 너비를 넘어가 가로 스크롤이 생기던 문제 → 모든 컬럼을 고정 너비로
  바꾸고, 넘치는 글자는 말줄임표(...)로 표시하며 마우스를 올리면 툴팁으로 전체 텍스트를
  볼 수 있습니다. 헤더 텍스트도 2줄까지 줄바꿈되도록 해서 좁은 너비에서도 읽기 쉽게
  했습니다. 창 크기(1880×1000)에서 21개 고정 컬럼 + `비고` 하나가 정확히 그리드 폭에
  맞습니다.
- **세로 열 단위 선택 복구**: 행 클릭 시 값 편집 패널이 안 열리는 문제를 고치려고
  `SelectionUnit` 을 기본값(`FullRow`)으로 되돌렸던 게, "채널이나 상품명 열만 세로로
  선택해서 복사"하는 기능을 다시 망가뜨렸습니다 → `SelectionUnit="CellOrRowHeader"` 로
  되돌리되, 이번에는 `SelectedItem` 을 뷰모델에 바인딩하지 않고(이게 예외의 원인이었음)
  `CurrentCellChanged` 이벤트로 "지금 클릭한 셀이 속한 행"을 코드비하인드에서 값 편집
  패널에 밀어 넣는 방식으로 바꿨습니다. 이제 셀을 클릭하면 그 행이 편집 패널에 뜨면서도,
  열 하나만 세로로 드래그해서 선택 후 복사하는 것도 그대로 가능합니다.
- **입력 창 디자인 정리**: "새 행사 만들기"(`TextInputDialog`), 비밀번호 확인
  (`PasswordDialog`) 창에 제목 텍스트와 앱 전체에서 쓰는 색상/버튼 스타일(파란 기본
  버튼 등)을 적용해 다른 창들과 톤을 맞췄습니다.

## 2.1.1 — 상품 추가 창에서 새 품목 등록 시 SKU/채널/금액 입력 안 되던 문제 수정

- **증상**: "상품 추가" 창에서 "새 품목 등록"을 누르면 상품명만 있는 빈 항목이 품목 마스터에
  추가될 뿐, SKU·채널·매입가(+)·기존정산액(+)을 입력할 방법이 없었음.
- **원인**: `AddMasterProduct_Click` 이 이름만 채운 `MasterProduct` 를 목록에 추가하고 끝나서,
  나머지 필드를 채울 입력란 자체가 창에 없었음.
- **수정**: `AddProductDialog` 에 목록에서 품목을 선택하면 나타나는 입력 패널을 추가해
  SKU/채널/매입가(+)/기존정산액(+)을 바로 입력·수정할 수 있게 했습니다. 새 품목을 등록하면
  이 패널이 자동으로 뜨고 SKU 입력란에 포커스가 가므로 바로 이어서 입력하면 됩니다. 나머지
  항목(행사가/스팟가/지원금 E·R/비고)은 기존처럼 "품목 마스터 관리" 창에서 입력합니다.

## 2.2.0 — 상품 추가 창 재구성: 금액 필드 제거, 검색/신규등록 분리

- **매입가(+)/기존정산액(+) 입력란 제거**: 상품 추가 창에서 이 두 금액을 수정하는 게 아니라
  품목 마스터에 이미 등록된 값을 그대로 쓰는 흐름이 맞다고 판단해, 해당 입력란을 없앴습니다.
  금액은 계속 "품목 마스터 관리" 창에서만 입력·수정합니다.
- **행사유형/비고 입력란 추가**: 대신 "이번에 추가하는 상품의 행사유형 / 비고" 칸을 새로
  넣었습니다. 이 두 값은 품목 마스터가 아니라 지금 만드는 상품 행에만 적용되는 값이라,
  품목을 선택하지 않아도 항상 입력할 수 있습니다. 예전에는 그리드가 읽기 전용이라 상품을
  추가한 뒤 행사유형/비고를 넣으려면 엑셀에서 복사해 붙여넣는 방법뿐이었는데, 이제 추가
  시점에 바로 입력할 수 있습니다.
- **검색창과 새 품목 등록 분리**: 예전에는 검색창에 이름을 입력해 "새 품목 등록"을 누르는
  구조라 검색과 등록이 뒤섞여 헷갈렸습니다 → 검색창은 목록 필터링 전용으로 남기고, 새
  품목 등록은 파란 테두리로 강조된 별도 카드(입력란 + "등록" 버튼)로 분리했습니다.
  "선택 삭제" 버튼은 SKU/채널 입력 카드 쪽으로 옮겼습니다(항목을 선택했을 때만 뜨는 카드라
  삭제 버튼도 그 자리가 자연스럽습니다).
